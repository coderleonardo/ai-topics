# Data Drift Detection — Notebooks

Four executable, exhaustive worked examples — one per detection family described in
[`docs/04-detecting-data-drift.md`](../docs/04-detecting-data-drift.md): **summary statistics**,
**statistical tests**, **distance metrics**, and **rule-based checks**.

All four notebooks analyze the exact same synthetic `reference` (historical/training-time) vs.
`current` (recent production batch) pair, generated by [`src/drift_dataset.py`](../src/drift_dataset.py)
with a fixed seed — a retail scenario continuing the one from `docs/01-what-is-data-drift.md`. That
dataset was built with a deliberate mix of signals, documented in `src/drift_dataset.py`'s
`COLUMN_DRIFT_GROUND_TRUTH` (and echoed as an "answer key" cell at the end of every notebook):

| column | what it actually does |
|---|---|
| `channel` | categorical share shifts (`in_store` → much more `online`) |
| `product_category` | a brand-new category (`online_exclusive`) appears only in `current` |
| `basket_size` | real drift: mean and variance both shift upward |
| `discount_pct` | a small, borderline shift — only reliably detectable at large sample sizes |
| `unit_price` | control feature — distribution is unchanged, nothing should fire |
| `customer_age` | not drift: a few corrupted values (`-1`, `-5`, `-999`) injected as a data-quality bug |

Because every notebook is scored against the same answer key, you can see directly where each
technique succeeds, and — just as important — where it doesn't. One genuine, useful finding that
came out of running these: the simplest mean-shift rule (±2 standard deviations) **misses**
`basket_size`'s real drift entirely, in both `01_summary_statistics.ipynb` and
`04_rule_based_checks.ipynb`, because that feature's natural variance is wide enough to absorb the
shift — while the statistical test and distance metrics in notebooks 02 and 03 catch it clearly.
That's not a contrived example; it's what the numbers actually showed when the notebooks were run.

## The notebooks

### `01_summary_statistics.ipynb`
Compares mean/median/std/quantiles and category proportions between `reference` and `current`, applies
a two-sigma mean-shift rule, and checks min-max range compliance (which catches the `customer_age`
data-quality bug, but — correctly — not `basket_size`'s drift, since a data-quality check isn't a
drift check).

**Use this when** you want the cheapest possible first pass, you already have domain expectations
about a feature's typical mean/median/range, or you need something simple enough to explain to a
non-technical stakeholder. Don't rely on it alone for features with high natural variance.

### `02_statistical_tests.ipynb`
Kolmogorov-Smirnov (numerical) and Chi-square (categorical) hypothesis tests, reported as p-values
against an alpha threshold. Includes a sample-size sensitivity experiment contrasting a control
feature (`unit_price`, no real drift — p-value stays noisy at every sample size) against a small real
effect (`discount_pct` — p-value only crosses the significance line once the sample is large).

**Use this when** you have a small number of important, interpretable features, a small-to-moderate
dataset, and a high-stakes domain (healthcare, finance) where a rigorous same-distribution test is
worth it. Be careful at large scale: tests get "overly sensitive" and will flag differences too small
to matter practically — that's exactly what the `discount_pct` experiment demonstrates.

### `03_distance_metrics.ipynb`
Wasserstein distance, Jensen-Shannon divergence, and a manually implemented Population Stability Index
(PSI, with the conventional `<0.1` / `0.1–0.25` / `>0.25` severity bands) for every feature, plus an
aggregate "share of drifted features" summary. Reruns the same sample-size experiment as notebook 02,
but the distance score stays roughly flat across sample sizes instead of collapsing toward
"significant" — the practical reason to prefer distance metrics at scale.

**Use this when** you're working with large production batches (where statistical tests become
oversensitive), or you want a magnitude you can track as a trend over time rather than a binary
same/different verdict. PSI's standard thresholds are a fast way to triage severity without needing
to reason about a p-value.

### `04_rule_based_checks.ipynb`
A small rule engine running four explicit threshold checks (category-share threshold, new-category
detection, out-of-range share, mean-shift threshold) against `current`, producing a pass/fail report.
Closes with a direct comparison to notebooks 02/03, including the mean-shift rule's miss on
`basket_size` described above.

**Use this when** you want the cheapest possible always-on alerting for things you already know
matter — a new category value, an impossible value range, a known-important feature crossing a
business-defined line. Rules don't generalize: they only catch what you explicitly wrote a check
for, and only as precisely as that check was tuned. Best paired with one of the other three
techniques for broader coverage.

## Running these notebooks

- Requires `numpy`, `pandas`, `scipy`, `matplotlib`, and `scikit-learn` (the last isn't used directly
  by the code but keeps parity with the rest of the repo's `src/`-backed notebooks). All were run
  under Python 3.10 via a dedicated Jupyter kernel, `data-drift-py310`
  (`python3.10 -m ipykernel install --user --name data-drift-py310 --display-name "Python 3.10 (data-drift)"`).
- Every notebook is committed with its outputs already executed, so you can read them top to bottom
  without running anything. To reproduce or modify: open in Jupyter, select the `data-drift-py310`
  kernel (or any Python environment with the packages above), and run all cells — the dataset is
  regenerated from a fixed seed, so results are deterministic.
- The shared dataset lives in [`../src/drift_dataset.py`](../src/drift_dataset.py); each notebook loads
  it via `sys.path.append(".."); from src import make_reference_and_current`, mirroring the
  `src/` + `notebooks/` convention used elsewhere in this repo (e.g. `machine-learning/`).
